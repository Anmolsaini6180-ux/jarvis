## Provider isolation and official compatibility

Official sources checked on 2026-10-11:
- https://ai.google.dev/gemini-api/docs/models/gemini-3.1-flash-live-preview
- https://ai.google.dev/gemini-api/docs/live-api/capabilities

Gemini 3.1 uses thinking levels, lacks proactive/affective audio and async function calling. It is now documented as a legacy preview. The application's existing model is retained; no automatic provider/model upgrade was made. Account eligibility, quota and availability cannot be inferred from documentation or successful TCP 443.

`tools/live_probe.py` shares the runtime's effective model, API version and compatibility builder. Without `--network` it only constructs/serializes actual SDK objects. Explicit network mode validates a single key locally, attempts bounded REST model metadata access, then separately checks acknowledged minimal Live setup and cumulative voice, transcription, synthetic diagnostic system instruction, tools, resumption/compression and optional fields. No microphone audio is sent, no tools execute, and personal memory/identity is omitted from the diagnostic prompt. A metadata 404 does not rule out preview Live support. Authentication/transport/quota failures stop early. A failed tool step triggers bounded individual-declaration isolation. Successful prior stages and skipped later stages are recorded separately. This can consume connection quota; run deliberately. Acknowledgment proves setup acceptance, not audibility or full conversation.

The application uses v1beta by default. `JARVIS_LIVE_API_VERSION` permits explicit v1alpha/v1beta selection and diagnostics use the same value. Unknown models omit unverified proactive/thinking/async options. Unsupported preferences are preserved on disk. Removing optional tuning after a setup rejection is process-local and is not silently restored by Retry Provider. Restart after deliberately correcting/revalidating tuning. Runtime payload rejection after an established session does not repeatedly try setup downgrade branches. 1007 is CONFIG, not proof of an invalid key. Authentication, malformed credentials, model access, policy, quota, DNS, TLS, timeout, network and unexpected runtime failures have separate safe messages.

Do not treat generated audio or stream writes as human-confirmed audible success.

Dashboard protocol changes require reloading/updating the phone page; existing code-only source replacement does not reset private desktop data. Pairing/session tokens are ephemeral and re-pairing may be required. Tokens are never written into the source ZIP. Socket tickets are short-lived single-use URL capabilities, not persistent bearer credentials; request logging must continue to avoid recording them. TLS must be trusted after out-of-band certificate verification; no firewall changes or certificate-check bypass was added. Plain authenticated command JSON still uses TLS and normal session/permission gates; non-idempotent commands are not automatically replayed by the UI.
